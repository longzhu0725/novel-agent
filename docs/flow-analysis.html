1 · 系统整体架构

┌─ 浏览器 (React + Vite + TS + Tailwind + zustand) ─────────────┐ │ ├─ ProjectList 书架（项目列表/CRUD） │ │ └─ Workspace 工作室（按阶段路由面板） │ │ ├─ PhaseNav 顶部书签（章回） │ │ ├─ FoundationPanel 基础设定（世界 + 人物） │ │ ├─ WritingPanel 撰文（大纲 + 章节树） │ │ ├─ ChapterList 章回（写作主区） │ │ ├─ AdvisorPanel 三顾问（随时可请益） │ │ └─ ChatPanel 与笔对坐（WS 双向流） │ └──┬────────────────────────────────────────────────┬───────────┘ │ REST /api/* │ WebSocket /ws/chat ▼ ▼ ┌─ FastAPI (uvicorn :8000) ─────────────────────────────────────┐ │ ├─ /api/projects|world|characters|outline|chapters| │ │ │ chat/history|advisors/{name} ← REST（CRUD） │ │ └─ /ws/chat ← WS（流式 + 事件）│ │ │ │ api/ 参数解析 │ │ └─→ storage/ 元信息→SQLite，正文→*.md 文件 │ │ ▲ │ │ agent/ │（不直接读写） │ │ ├─ agent.py Agent 主循环（流式 delta 实时落盘） │ │ ├─ tools.py 工具注册表 + 阶段门控 │ │ ├─ prompts.py 各阶段 system prompt 模板 │ │ ├─ subagents.py 3 个顾问 sub-agent │ │ └─ sessions.py WS 会话注册 + 跨窗口事件总线 │ │ │ │ │ ▼ │ │ core/ │ │ ├─ llm.py LLMClient（httpx 裸调，OpenAI 兼容） │ │ ├─ state_machine.py 5 阶段 + 转移规则 │ │ ├─ compression.py 80% 触发，保留 70% tail │ │ └─ errors.py ProtocolError + ErrorCode │ └──────────────────────────────────────────────────────────────┘ │ │ └─→ 火山方舟 / OpenAI / DeepSeek / vLLM ───┘

分层不变量

  • api/ 只做参数解析，不写业务
  • agent/ 调 LLM / 调工具，不直接读写 DB / 文件
  • storage/ 是唯一能摸磁盘的地方
  • 任何全局状态从 core/ 取；错误用 core/errors.py 的协议错误

2 · 阶段状态机（流程的骨架）

定义在 backend/app/core/state_machine.py：

INIT ──► FOUNDATION ──► WRITING ──► DONE │ │ │ └──────────┴──────────────┘ （任意阶段可回退修订）

转移规则

  • 向前一格：INIT → FOUNDATION → WRITING → DONE，合法
  • 向后任意格：合法（用户改主意，回到前一卷再写）
  • 自转移（WRITING → WRITING）：非法
  • 跳级（INIT → WRITING）：非法
  • 旧版本 5 阶段 WORLD/CHARACTERS/OUTLINE/WRITING/DONE 的项目在 init_schema() 时自动迁移到新版本（WORLD/CHARACTERS → FOUNDATION，OUTLINE → WRITING），迁移函数 migrate_legacy_phase()

3 · 八步创作流程

STEP 01
起念
ProjectList 输入书名 → POST /projects → SQLite 落库 → 跳转 Workspace
STEP 02
阶段引导
INIT 阶段：提示页 + 右侧 ChatPanel，与笔谈构想
STEP 03
Foundation
基础设定：WorldEditor（世界 markdown） + CharacterList（人物卡 CRUD）
STEP 04
与笔对坐
WS 流式：delta 增量推送，LLM 调工具，10 轮上限，可中断
STEP 05
Writing
撰文：OutlineTree 选节点 → ChapterList 写章节，流式落盘
STEP 06
顾问
AdvisorPanel 三个按钮：outline / style / review，独立 sub-agent
STEP 07
回退
PhaseNav 弹 portal modal 确认回退，状态机允许向后任意格
STEP 08
完稿
WRITING → DONE，ChapterList 升主区，完整阅读模式

步骤 4 详解：ChatPanel 与 WebSocket 协作

  1. 连接：new ChatSocket(sid, pid) → 走 Vite 代理 → 后端 ws.py
  2. 拉历史：GET /chat/history?session_id=... → 渲染
  3. 发消息：按 Enter → send(text) → WS 发 {type:"chat.message", text, correlation_id}
  4. 后端处理（api/ws.py + agent/agent.py）：
    • 拉项目 + 阶段 + 上下文摘要
    • 上下文压缩：历史消息总长 > 80% 窗口时触发，丢最早 30% → 500 字 summary → 保留 70% tail
    • 拼 system prompt（prompts.py build_system_prompt）
    • 喂给 LLM（core/llm.py，httpx 裸调，可注入 mock）
    • 流式接收：每个 chat.delta 一边推回前端、一边若处于"流式章节"模式则 _append_delta 落盘
  5. 工具调用：LLM 返回 tool_calls → Agent 派发到 tools.py，按 allowed_phases 校验 → 执行后写回 chat.tool_result → 再喂 LLM（循环最多 10 轮）
  6. 结束：chat.done { message_id, usage }

前端 ChatPanel.tsx 收到 delta 就把它 set((s)=>({streaming: s.streaming + ev.text}))，收到 done 把 streaming 整段推到 messages 数组。

6 · 工具集与流式章节

工具在 backend/app/agent/tools.py 注册，由 allowed_phases 门控（合并后阶段名）：

阶段工具
FOUNDATIONupsert_world_doc / read_world_doc / create_character / update_character / list_characters
WRITINGcreate_outline_node / update_outline_node / list_outline / create_chapter / begin_chapter / append_to_chapter / finalize_chapter / read_chapter
任意advance_phase / read_project_summary / consult_outline_expert / consult_style_expert / consult_reviewer

流式章节三件套（合并后保留的"超 v0"能力）

  1. LLM 调 begin_chapter({title, order, outline_node_id?}) → 后端建章节，状态 DRAFT_PARTIAL，Agent 记下 streaming_chapter_id
  2. 后续 LLM 的每个 chat.delta → Agent 主循环发现处于"流式章节" → _append_delta 同步写 SQLite + 落 0001_*.md
  3. LLM 调 finalize_chapter({chapter_id}) → 状态 DRAFT，跳出 Agent loop

7 · 顾问 sub-agent

3 个 sub-agent 调同一个 LLM，但用不同系统提示侧重不同维度：

Advisor用途入口
outline_expert结构 / 伏笔 / 节奏REST + 函数
style_expert文风一致性（参数带原文 + focus）REST + 函数
reviewer一致性 / 人设 / 设定自洽REST + 函数

实现：agent/subagents.py，3 套 system prompt + 独立会话。

8 · 当前已跑通的链路

  • RUNNING 后端 uvicorn app.main:app 监听 0.0.0.0:8000，lifespan 启动时 init_schema
  • RUNNING 前端 vite --host 0.0.0.0 监听 5173，/api / /ws 代理到 8000
  • CONFIGURED .env 已配置火山方舟端点 + 测试 key
  • OK ProjectList 增删查 → SQLite；Workspace 三 tab
  • OK AdvisorPanel 三个按钮 → REST → 3 sub-agent → 实时回显
  • OK ChatPanel 走 WS 流式，chat.delta 增量渲染
  • OK PhaseNav 点击 → 状态机校验 → 切阶段

常见排错

  • 注意 没填 .env → 顾问 / 章节 / 对话都走不通，但项目 CRUD 没事
  • 注意 端口被占 → 改 --port 和 Vite 的 proxy
  • 注意 浏览器 CORS：避免直连 8000，始终用 5173，让 Vite 代理
